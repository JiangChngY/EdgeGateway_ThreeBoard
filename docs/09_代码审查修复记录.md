# 代码审查与改进记录

修复日期：2026-08-09

## 审查项处理结果

| 编号 | 结论 | 处理 |
|---:|---|---|
| 1 | 原报告对旧代码bit 0分支的解释不准确：`wait_level()`返回1后，`if (!1)`不会失败。但旧写法确实难读且依赖35μs采样点。 | DHT11改为使用TIM4微秒计数器直接测量高脉宽，约28μs判0、约70μs判1，45μs为分界。 |
| 2 | 确认存在本地阈值先更新、F103未确认时状态分歧的风险。 | MP157仅在收到成功COMMAND_ACK后提交并保存阈值；2.5秒超时、断线或拒绝时恢复旧值。F103上报的alarm成为真实模式的唯一权威状态。 |
| 3 | 确认每条MQTT消息启动一次进程开销偏大。 | 改为常驻 `mosquitto_pub -l -q 1`，通过stdin逐行发布；增加进程错误、退出重试和队列满日志。原始数据仍保存在SQLite。 |
| 4 | “MP157积压数据全部丢失”不成立，因为未收到ACK的数据仍在MP157 SQLite队列中；但服务端原先先判断1MB再拆行不合理。 | 改为先逐行处理，单行上限64KiB；无换行超限时先返回负ACK再断开，MP157保留未确认数据。 |
| 5 | 确认少量曲线点被挤在左侧。 | X轴分母改为当前序列 `values.size()-1`，数据不足120点时也铺满曲线区域。 |
| 6 | 确认报警复位后高温持续会立即再次触发。 | 增加消音状态与1℃回差；复位后保持消音，温度低于“阈值-1℃”才重新布防。 |
| 7 | `0u`可转换为空指针但表达不清。 | 心跳调用改为显式 `NULL`。 |
| 8 | 确认HMI没有使用有效位控制显示。 | HMI无效字段显示`--`、禁止无效温湿度报警判断；SQLite写NULL；上报增加valid_flags和JSON null；i.MX6ULL数据库自动迁移valid_flags列。 |
| 9 | 确认异常长度ACK被静默忽略。 | 非2字节COMMAND_ACK现在触发协议错误提示，等待中的阈值命令最终超时回滚。 |
| 10 | 确认API跨域调试不方便。 | HTTP加入CORS响应头及OPTIONS/204预检响应。 |
| 11 | 兼容接口只能用0表示失败。 | 新增 `eg_build_frame_ex()` 与三类错误码；旧接口保留，MP157命令构帧改用扩展接口。 |
| 12 | 确认重复安装会覆盖现场配置。 | 安装脚本默认保留已有INI；只有显式传入 `--force-config` 才覆盖。 |

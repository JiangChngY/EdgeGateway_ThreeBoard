SDK 使用运行用户的 `$HOME` 定位目录。6ULL 单独使用其原有目标运行库，不替换板端 libc 或 Qt。

## 新上报协议

TCP 9000：一行一个 UTF-8 JSON。下例为合成测试数据：

```json
{"type":"sensor","schema":2,"board":"F103ZE","gateway":"mp157-<database-uuid>","seq":42,"source_seq":65535,"valid_flags":15,"temperature":25.5,"humidity":61,"ntc":2048,"millivolts":1650,"distance":356,"digital":1,"synthetic":false}
```

ZE 有效位：bit0 温湿度，bit1 NTC ADC/mV，bit2 距离，bit3 DO。无效字段为 null，数据库也保存 NULL。C8 使用 schema 1，bit1/bit2 仍分别表示光照/模拟量。

确认：`{"type":"ack","seq":42,"ok":true}`。错误序号、无效 JSON、非布尔 ok 不会删除数据。拒收、5 秒超时或断线均保留条目重试。汇聚端 `(gateway,seq)` 唯一索引避免确认丢失造成重复入库。

更新后新样本同时进入历史和队列，不自动回灌更新前的旧历史。暂停上传仍排队，暂停采集不再接收新样本。队列上限 100000，内存待写上限 128，达到上限显示未保存提示。

## 接板验收

1. Ubuntu 网卡 ens33/37/38 分别为 192.168.88.131、192.168.137.2、192.168.138.2。
2. 两块板按原 TFTP/NFS 配置启动；MP157=192.168.137.3，6ULL=192.168.138.3，6ULL 网线接 ENET1。
3. 6ULL 执行 `ps | grep edge-aggregator`、`netstat -lnt`，检查 9000/8080。手动启动：`/etc/init.d/edge-aggregator start`。
4. MP157 执行 `systemctl status edge-peer-route.service systemui.service`，确认 `ip route get 192.168.138.3` 经 192.168.137.2。
5. F103 USART2 经 USB-TTL 接 MP157 USB HOST；边缘采集选择实际串口。USART1 调试文字不是这里的二进制输入。
6. 核对真实温湿度、NTC、距离、DO 随实物变化；无效读数应隐藏。NTC 尚不直接换算温度。
7. 「汇聚上传」连接 192.168.138.3:9000，待确认回到 0。在 Ubuntu 访问 `http://192.168.138.3:8080/api/latest` 核对同一笔数据。
8. 用「暂停上传」模拟业务中断，采集继续、队列增加；重新连接后队列归零。NFS 启动期间不要拔掉承载根文件系统的网线做此试验。

## 回退与边界

先停止两块板的应用或关闭板子，再在 Ubuntu 运行本次确切备份目录中的 `sudo bash rollback.sh`。回退保留传感器数据库，旧程序忽略新增列。

使用 eMMC 原系统不会自动获得 NFS 中的新 App；此次不刷写 eMMC、U-Boot 或设备树。主机与 ARM/QEMU 检查均使用合成输入，实物屏幕、触摸、接线和传感器仍需上板验收。
